# 8.1. BullMQ Module

A dynamic module that registers one or more BullMQ queues behind a single config factory.

## Import

```typescript
import { BullMQModule } from '@triplef/bullmq';
```

## Interface

```typescript
interface BullMQModuleProps {
  imports?: ModuleMetadata['imports'];
  global?: boolean;
  inject: Array<any>;
  queues: Queue[];            // string | { name: string; connection?: RedisOptions }
  processors: Array<Provider>;
  useFactory: BullMQConfigFactory; // (...deps) => Promise<BullMQConfig> | BullMQConfig
}
```

### Options

| Option | Type | Description |
|--------|------|-------------|
| `imports` | `ModuleMetadata['imports']` | Additional modules imported alongside the BullMQ queues |
| `global` | `boolean` | If `true`, the registered queues are available application-wide |
| `inject` | `Array<any>` | Providers injected into `useFactory` |
| `queues` | `Queue[]` | Queue names and/or `{ name, connection }` objects to register |
| `processors` | `Array<Provider>` | Processor providers attached to the module |
| `useFactory` | `BullMQConfigFactory` | Factory returning the base `BullMQConfig` (connection, `defaultJobOptions`) |

## Usage

```typescript
import { Module } from '@nestjs/common';
import { BullMQModule } from '@triplef/bullmq';
import { MyBullMQConfigService } from './bullmq-config.service';
import { MyProcessor } from './my.processor';

@Module({
  imports: [
    BullMQModule.registerAsync({
      global: true,
      inject: [MyBullMQConfigService],
      queues: ['harness', { name: 'vectorize', connection: { host: 'keydb' } }],
      processors: [MyProcessor],
      useFactory: (config: MyBullMQConfigService) => config.options,
    }),
  ],
})
export class AppModule {}
```

The env-driven config lives in the consuming app — the library ships no config service and reads no environment variables.

## Queue Registration

- Each queue entry is registered with `BullModule.registerQueueAsync`.
- A queue-level `connection` overrides the factory's `connection` for that queue.
- `imports` placed before the BullMQ queues are kept in order.
