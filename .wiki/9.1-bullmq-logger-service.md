# 9.1. BullMQ-Logger Service

A NestJS `LoggerService` for BullMQ `Job` objects. Each call resolves the job state and renders a message with an emoji state icon.

## Import

```typescript
import { BullMQLoggerService } from '@triplef/bullmq-logger';
```

## Methods

| Method | pino level | Payload |
| --- | --- | --- |
| `log(job, type?)` | `info` | Message only |
| `error(job, type?)` | `error` | Message + `failedReason`/`stacktrace` when the state is `failed` |
| `warn(job, type?)` | `warn` | Message + queue, attempts, delay, timestamps |
| `debug(job, type?)` | `debug` | Message + queue, timestamp, `opts`, `data` |
| `verbose(job, type?)` | `trace` | Full job object + message |

`type` is an optional override: `JobType | JobState | 'canceled' | 'error' | 'stalled' | 'unknown'`.

## State Icons

| State | Icon |
| --- | --- |
| `completed` | 🟢 |
| `error` | 🔴 |
| `failed` | ⚫ |
| `delayed` | 🟠 |
| `waiting` | 🟡 |
| `prioritized` | 🔵 |
| `active` | 🟣 |
| `waiting-children` | 🟤 |
| `paused` | ⚪ |
| `stalled` | 🔘 |
| `canceled` | ⭕ |
| other | 🚫 |

## Safe State Inference

The service checks for `job.getState()` and falls back to job properties when it is unavailable (e.g. BullMQ v5 error events):

1. `failedReason` set → `failed`
2. `finishedOn` set → `completed`
3. `processedOn` set → `active`
4. otherwise → `error`

## Usage

```typescript
import { Injectable } from '@nestjs/common';
import { BullMQLoggerService } from '@triplef/bullmq-logger';

@Injectable()
export class MyProcessor {
  constructor(private readonly logger: BullMQLoggerService) {}

  async process(job: Job) {
    await this.logger.log(job);
  }
}
```

The underlying pino instance is exposed via the `pino` getter (initialized in `onModuleInit`).
