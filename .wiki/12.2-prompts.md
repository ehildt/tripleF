# 12.2. Agent Prompts

`@triplef/agent/prompts` — every prompt the two apps send to a model, centralized so the model contract is edited once.

## Import

```typescript
import { /* … */ } from '@triplef/agent/prompts';
```

## Harness prompts (`harness/`)

| Export | Role |
| --- | --- |
| `base-system.prompt` | The base system prompt (identity, rules, media/grounding policy). |
| `content-system.prompt` | Content-answer system prompt (+ its types). |
| `intent-selection.prompt` | The classifier prompt driving the interpret step (see **1.2**). |
| `structured-json-prompt.constant` | The structured-output instruction wrapping variant schemas. |
| `variant-instructions.registry` | Maps each intent template to its variant instruction set. |
| `helpers/` | `build-context-summary-section`, `tool-catalog` (renders enabled tools into prompts), `variant-catalog`, `resolve-language-name`. |

## Per-variant instructions (`instructions/`)

One instruction file per rigid template: `compare`, `describe`, `imagelist`, `international-coverage`, `ocr`, `product`, `shoplist`, `stockmarketitem`, `stockmarketlist`, `summary`, `text`, `videolist` — plus `helpers/build-structured-prompt.helper`.

## Snippet-composed presets (`snippets/`)

`news.preset`, `article.preset`, `evaluation.preset` (and `merge.preset`) compose their templates from reusable snippets — headers, lead, key findings, sources, gallery, video gallery, related stories, comparison, assessment lists, verdict spine, reasoning, byline/dateline, author meta, hero media, introduction/conclusion, layout, quote, subjects, summary, body variants — declared in `snippet-presets.constant` (with the `helpers/` — `composeSnippetSchema`, `composeSnippetKeys`, `buildSnippetInstruction`). The preset owns its Zod schema *and* its instruction set, so the model contract stays declarative per template; validation runs server-side in the harness response validators (see **1.2 — Prompts & structured outputs**).

## Memory job prompts (`memory/`)

| Export | Job (memory app, see **1.7**) |
| --- | --- |
| `vectorize-prompt.constant` | The fact-extraction step (extract → embed → store). |
| `memory-write-prompt.constant` | `memory-write` — lane-routed remember decisions over the turn's gathered results. |
| `memory-profile-prompt.constant` | `memory-profile` — the cognition profile patch + insights + episode verdict (**1.6**). |
| `memory-consolidate-prompt.constant` | Merge verdicts of the consolidation sweep. |
| `memory-enrich-prompt.constant` | Category-collapse enrichment used by the relink job. |
| `memory-cluster-prompt.constant` | Cluster title/summary generation. |

## Shared fragments (`shared/`)

Reusable rule blocks mixed into prompts as needed: `commonmark-format`, `final-reminder`, `history-urls`, `image-task-rule`, `item-shapes`, `json-rules`, `language-rule`, `localization-rule`, `media-counts`, `media-rules`, `merge-rules`, `multimodal-policy`, `noise-rules`, `output-contract`, `precedence-rules`, `security-rules`, `source-policy`, `source-truth`, `source-voice`, `tool-results`.

The localization chain is worth calling out: `language-rule` + `localization-rule` + `resolve-language-name` turn the request's `language` query param (see **1.1**) into the answer's language contract.
