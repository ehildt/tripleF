# 0.1. Quick Start

From a fresh clone to a running 3F stack in a few commands. Everything happens inside containers — the main host requirements are Docker, `git`, `pnpm`, and (optionally) Ollama for local inference.

```bash
git clone https://github.com/ehildt/tripleF.git && cd tripleF
```

## Prerequisites

| Requirement                                                      | Purpose                                                  |
| ---------------------------------------------------------------- | -------------------------------------------------------- |
| `git`                                                            | Clone the repo (above)                                   |
| [`pnpm`](https://pnpm.io/installation) (`11.x`)                  | Used once to push the DB schema (step 3)                 |
| Docker + Docker Compose v2 (with BuildKit)                       | All services run containerised                           |
| [Ollama](https://ollama.com/) (optional)                       | Local model inference; skip when using Ollama Cloud only |
| An Ollama model with vision support (e.g. `qwen3-vl`, `llava`) | Image/chat intelligence, `ollama pull <model>`           |
| `SERPER_API_KEY` (optional)                                    | Web/news/image/video search tools for the agent          |
| `BRIGHT_DATA_API_KEY` (optional)                              | Alternative search provider (SERP + Web Unlocker)       |
| `YOUTUBE_API_KEY` (optional)                                   | YouTube Data API v3 video search for the agent           |

## 1 — Environment files

```bash
cp apps/server/.env.example apps/server/.env
cp apps/memory/.env.example apps/memory/.env
cp apps/dashboard/.env.example apps/dashboard/.env
```

The committed examples are ready for local development. See **0.2-docker** for the full contract and **1.8** for every variable and what it changes. Important keys:

| Variable         | Default (local)                          | Notes                                                           |
| ---------------- | ---------------------------------------- | --------------------------------------------------------------- |
| `OLLAMA_HOST`    | `http://host.docker.internal:11434/api`  | Set to `https://ollama.com/api` + `OLLAMA_API_KEY` for Ollama Cloud |
| `MEMORY_ENABLED` | `true`                                   | Semantic memory is on by default; set `false` to run without it |
| `QDRANT_URL`     | `http://qdrant:6333`                     | Vector store for memory + encyclopedia (loopback-only in infra)      |
| `QDRANT_EMBED_MODEL` | `nomic-embed-text-v2-moe`            | Embedding model for memory chunks (768-dim)                     |
| `SERPER_API_KEY`  | —                                        | Enables Serper tools (search, images, news, videos …)           |
| `BRIGHT_DATA_API_KEY` | —                                    | Enables Bright Data tools (alternative to Serper; SERP + Web Unlocker) |
| `YOUTUBE_API_KEY` | —                                        | Enables the YouTube video search tool (Data API v3)             |
| `TRIPLEF_SECRETS_KEY` | —                                    | AES-256-GCM master key for Settings-persisted API keys (`openssl rand -hex 32`) |
| `POSTGRES_URL`   | in-network DSN (`postgres:5432`)               | Shared by server and memory app             |

The memory app (`apps/memory/.env`) carries the Qdrant/encyclopedia/cognition knobs — `QDRANT_*` (server-side only `MEMORY_URL`/`MEMORY_ENABLED` point at the app), `MEMORY_*` and `ENCYCLOPEDIA_*` — all with code fallbacks, so the committed example works as-is. The constellation node limit (`MEMORY_CONSTELLATION_NODE_LIMIT`, default `5000`) and the encyclopedia persistence switch (`ENCYCLOPEDIA_PERSIST_ENABLED`, default `true`) are the two you are most likely to touch.

## 2 — Start the infrastructure

```bash
docker compose -f infra.compose.yml up -d
```

Brings up **PostgreSQL 16** (`5432`), **MinIO** (`9000`, console `9001`), **KeyDB** (`6379`, configured by `apps/server/keydb.conf`), **Qdrant** (`6333`, loopback-only), and a **`playwright-mcp`** headless-chromium sidecar (loopback-only on `8931`) that exposes `browser_*` automation tools to the harness (see **1.2**). Ollama is included but commented out — enable it if you want containerised inference.

## 3 — Push the database schema

```bash
pnpm --filter server db:push
```

The server owns the Prisma schema (the memory app only generates a client against the shared tables). This pushes the schema to the local Postgres — reachable at `localhost:5432` via the infra port mapping. Run it once after the first `infra.compose.yml up`, and again whenever `apps/server/prisma/schema.prisma` changes.

## 4 — Start the application

```bash
docker compose up -d
```

That's it. Compose builds one shared image (`triplef-local`) and starts four services:

1. **`deps`** (one-shot) — runs `pnpm install --frozen-lockfile` for the entire workspace from the repo root and exits. It is the _only_ component allowed to touch `node_modules`.
2. **`server`** — waits for `deps` and `memory`, then starts the NestJS harness in watch mode at `http://localhost:3000` (API under `/api/v1`, Swagger at `/api-docs`).
3. **`memory`** — waits for `deps`, then starts the NestJS memory app (Qdrant/encyclopedia/cognition) at `http://localhost:3400` (API under `/api/v1`, Swagger at `/api-docs`).
4. **`dashboard`** — waits for `server`, then starts Vite at `http://localhost:5173/dashboard/`.

All app services bind-mount the repository and hot-reload on save. No restarts or rebuilds are needed for source changes under `apps/server/`, `apps/memory/`, or `apps/dashboard/`.

## 5 — Verify

The one check that actually matters: open **`http://localhost:5173/dashboard/`** in your browser — when the dashboard loads, the stack is up. Pick a model and start talking.

Optional, if you want to confirm each service from the terminal:

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/api/v1/health/live   # 200 (server)
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3400/api/v1/health/live   # 200 (memory)
docker compose ps                                                                   # server/memory/dashboard Up, deps Exited (0)
```

## Daily workflow

| Task                               | Command                                                                              |
| ---------------------------------- | ------------------------------------------------------------------------------------ |
| Start everything                   | `docker compose -f infra.compose.yml up -d && docker compose up -d`                  |
| Follow server logs                 | `docker compose logs -f server`                                                      |
| Follow memory logs                 | `docker compose logs -f memory`                                                      |
| Stop the app (keep infra)          | `docker compose down`                                                                |
| Stop everything                    | `docker compose down && docker compose -f infra.compose.yml down`                    |
| Re-install deps (lockfile changed) | `docker compose up deps && docker compose up -d --force-recreate`                    |
| Run scripts inside containers      | `docker compose exec server pnpm <cmd>` · `docker compose exec memory pnpm <cmd>` · `docker compose exec dashboard pnpm <cmd>` |

## Rules that keep the stack healthy

1. **Install only at the repo root** — `pnpm install`, `pnpm --filter server add <pkg>`. Installing _inside_ an app against stale standalone state can flip `node_modules` back to a per-app layout (and per-app lockfiles). The `deps` service guarantees containers stay on the shared workspace layout — see **0.2-docker** for why.
2. **Never delete `node_modules`** as a troubleshooting step. That was a workaround for the old dual-lockfile regime; the current setup makes it unnecessary and harmful.
3. If state _did_ drift (e.g. after running standalone Dockerfiles), the deterministic reset is: `rm -rf apps/server/node_modules apps/memory/node_modules apps/dashboard/node_modules node_modules && docker compose up -d --force-recreate`.

## Tests & quality gates

```bash
pnpm -r test          # Vitest across all workspaces
pnpm -r lint          # ESLint + Prettier (flat configs)
pnpm -r depcruise     # dependency-cruiser architecture rules
pnpm -r lint:unused   # ts-unused-exports
```

CI runs the same gates on every branch (`non-release.ci.yml`); `main` additionally versions with changesets and regenerates badges (`release.ci.yml`, see **0.3-documentation**).
