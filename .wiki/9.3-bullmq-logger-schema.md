# 9.3. BullMQ-Logger Schema

A Joi schema for validating pino `LoggerOptions`. Exported so consumers can validate their own pino config (e.g. via `@ValidateReturnValue`) before handing it to `BullMQLoggerModule.registerAsync`.

## Import

```typescript
import { BullMQLoggerSchema } from '@triplef/bullmq-logger';
```

## Fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `level` | `string` | `info` | One of `fatal`, `error`, `warn`, `info`, `debug`, `trace`, `silent` |
| `base` | `object \| null` | — | pino `base` (keys added to every log line) |
| `redact.paths` | `string[]` | — | Secret-shaped paths to redact (e.g. `apiKey`, `*.token`, `req.headers.authorization`) |
| `redact.censor` | `string` | — | Replacement value (e.g. `[REDACTED]`) |
| `timestamp` | `function \| boolean` | — | Custom timestamp function, or `false` to disable |
| `transport.target` | `string` | `pino-pretty` | Transport target |
| `transport.options.translateTime` | `string` | `yyyy-mm-dd HH:MM:ss.l` | Timestamp format |
| `transport.options.colorize` | `boolean` | `true` | Colorize output |
| `transport.options.ignore` | `string` | `pid,hostname` | Keys hidden from pretty output |

`timestamp` and `transport` are optional — pino's defaults apply when omitted. Unknown keys are allowed (`.unknown(true)`).

## Usage

```typescript
import { Injectable } from '@nestjs/common';
import { ValidateReturnValue } from '@triplef/config-factory/validate-return-value';
import { BullMQLoggerSchema } from '@triplef/bullmq-logger';

@Injectable()
export class LoggerConfigService {
  @ValidateReturnValue(BullMQLoggerSchema)
  get options() {
    return {
      level: process.env.BULLMQ_LOG_LEVEL || 'info',
      redact: {
        paths: ['apiKey', '*.apiKey', 'req.headers.authorization'],
        censor: '[REDACTED]',
      },
      transport: {
        target: 'pino-pretty',
        options: { ignore: 'pid,hostname' },
      },
    };
  }
}
```
