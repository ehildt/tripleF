# 12.4. Quick Start

## Installation

```bash
npm install @triplef/agent
```

Install peer dependencies:

```bash
npm install ai zod
```

## Usage Examples

### Tooling a model with dependency injection

Tool factories take `ToolDependencies` — a `getLiveConfig()` snapshot accessor (resolved per call, so runtime overrides apply without a restart), a `logger`, and optional `notify`/`model` wiring:

```typescript
import { createSerperWebSearch, withSummary } from '@triplef/agent/tools';
import { generateText } from 'ai';

const serperWebSearch = createSerperWebSearch({
  getLiveConfig: () => providerConfig, // your resolved ProviderConfig
  logger: console,
});

const { text } = await generateText({
  model, // from your provider (e.g. ollama-ai-provider-v2)
  prompt: 'What happened in spaceflight this week?',
  tools: { serperWebSearch },
});
```

### Validating a structured answer against a variant schema

```typescript
import { compareSchema } from '@triplef/agent/schemas';

const parsed = compareSchema.safeParse(modelOutput);
if (!parsed.success) {
  // repair or reject — the harness's response validators do exactly this (1.2)
}
```

### Building a system prompt with shared rules

```typescript
import { buildBaseSystemPrompt, buildStructuredPrompt } from '@triplef/agent/prompts';

const system = buildBaseSystemPrompt({ hasImages: true });
```

### Memory tools need a scope

Memory tools are created with a `MemoryToolScope` (partition/cognition binding + provenance ids) plus injected store/search callbacks, so a request's tools can never cross space boundaries:

```typescript
import { createMemoryPartitionRecallTool } from '@triplef/agent/tools';

const recall = createMemoryPartitionRecallTool({
  scope: { memoryPartition, memoryCognition, sessionId, conversationId, requestId },
  searchByText: (input) => memoryClient.searchByText(input),
});
```
