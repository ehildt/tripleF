# 1.8. Runtime Configuration & System Variables

3F is deliberately **config-driven**: the same codebase runs as a fully-offline local chat or as a cloud-backed research workbench depending on configuration. This page maps every layer of configuration and, for each knob, **what behavior it changes, where it is stored, and when it takes effect**.

## The four layers

Configuration resolves in four layers, each sharper than the previous:

| # | Layer | Storage | Takes effect | Survives restart |
| --- | --- | --- | --- | --- |
| 1 | **Env baselines** | `.env` files → `process.env`, Joi-validated at boot | next boot | yes (by definition) |
| 2 | **Global persisted overrides** (SysCtl) | PostgreSQL `harness_provider_override` rows | **the very next request** | yes — restored on boot |
| 3 | **Global ephemeral overrides** | in-memory only | the very next request | no — env remains the baseline |
| 4 | **Per-session / per-request** | `harness_config` row / the `POST /harness` query itself | per session / per turn | session config yes |

Layering rule everywhere: **override → env baseline → code default**, each numeric clamped into its supported envelope at read time. Consumers resolve the effective value *at execution time*, never at boot registration — that is what makes a SysCtl write apply to the next query without a restart.

### Layer 1 — env baselines

Both apps validate their complete env at boot through `@triplef/config-factory` (invalid env = fast fail). The `.env.example` files are the authoritative inventory, sorted by module; the committed examples are tuned for local dev. These are **pristine baselines** — for the subsystems marked "SysCtl" below they are not the live values, because layers 2–3 override them at runtime.

### Layer 2 — persisted global overrides (PostgreSQL)

| Surface | Row key(s) | Persisted | API keys at rest |
| --- | --- | --- | --- |
| `/provider-overrides` | `serper`, `brightData`, `eodhd`, `youtube`, `sources` | yes | encrypted (AES-256-GCM), masked on read |
| `/ollama-overrides` | `ollama` | yes | encrypted, masked on read |
| `/memory-overrides` (memory app) | `memory` | yes | n/a (no keys) |

All are written from the dashboard's **SysCtl** area, restored on boot (with a lazy throttled retry if the database was slow), and honored on the next request. `DELETE` on the surface clears back to the env baseline. The legacy `webpageFetch` key is migrated to `scrape` on read.

### Layer 3 — ephemeral global overrides

`/sharp-overrides` (image preprocessing, `PPROC_*` envs as baseline) is **in-memory by design**: SysCtl writes apply immediately, a restart returns to env. This keeps a shared, experiment-friendly knob out of the durable store.

### Layer 4 — per-session and per-request

- **`harness_config` row per session** (`PUT /configs/:sessionId` — see **1.5**): `selectedModel`, `preprocessing`, `providerOverrides`, and the memory space ids `memoryPartition` / `memoryCognition`. The dashboard pushes persisted preprocessing settings to the server on boot so server-effective config matches the UI.
- **`POST /harness` query params per turn**: `numCtx` (context window), `think` (reasoning phase), `stream`, `language` (UI locale → answer language), `memoryPartition` / `memoryCognition` (which memory spaces this turn reads/personalizes against), `graphRag` (link-graph probes for this request), `event`/`roomId` (real-time routing), `sessionMetadata` (image hashes for dedup — see **1.1**).

## What each knob changes — server (`apps/server/.env`)

### App server & observability

| Variable(s) | Behavior |
| --- | --- |
| `PORT`, `ADDRESS`, `NODE_ENV`, `BODY_LIMIT` | Listener binding and Fastify body cap (both **required** — boot validation fails without them). |
| `PRINT_CONFIG` | Dumps the resolved config at boot. |
| `ENABLE_SWAGGER` | Mounts Swagger at `/api-docs` when true. |
| `LOGGER_*` | Pino level, pretty/JSON, transport targets; merged base bindings via `LOGGER_BASE`. |
| `HEALTH_*` | `/health/ready` thresholds (heap/RSS, disk path + threshold percent). |
| `CORS_*` | Fastify CORS (origins, methods, credentials; `CORS_ALLOWED_HEADERS` must carry `x-harness-llm`). |

### Model runtime (Ollama)

| Variable(s) | Behavior |
| --- | --- |
| `OLLAMA_HOST` + `OLLAMA_API_KEY` | **The** locality switch: `http://host.docker.internal:11434/api` = local Ollama; `https://ollama.com/api` + API key = Ollama Cloud. Drives the model catalogue (`GET /harness/models` ETag), warm-up, and every model call. Runtime-overridable via `/ollama-overrides` (SysCtl). |
| `OLLAMA_KEEP_ALIVE` | How long Ollama keeps weights loaded between calls. |
| `OLLAMA_STREAM_CHUNK_TIMEOUT_MS` / `OLLAMA_STREAM_TOTAL_TIMEOUT_MS` | Abort a stream after 60 s without a chunk / 10 min total — a hung model becomes an inline error event instead of a stuck exchange. |
| `OLLAMA_GENERATE_TOTAL_TIMEOUT_MS` | 5 min ceiling for non-streaming (structured) calls. |
| `OLLAMA_ENABLE_SMOOTH_STREAM` | Word-level smooth streaming to the UI (default on; set false for raw chunk bursts). |
| `NUM_CTX` | Comma-separated context sizes offered to the model selector and consumed by the dashboard's context-window readout. |

### Harness budgets (context economy)

| Variable(s) | Behavior |
| --- | --- |
| `HARNESS_IMAGE_DOWNLOAD_TIMEOUT_MS` | Per-cloud-image download abort (8 s). |
| `HARNESS_SOURCE_BUDGET_RATIO` / `HARNESS_SOURCE_BUDGET_CHARS` | Share of `numCtx` reserved for fetched-source selection (fallback absolute chars). |
| `HARNESS_REFERENCE_DOC_RATIO` / `HARNESS_REFERENCE_DOC_CHARS` | Per-document ceiling before chunk/embed via the encyclopedia. |
| `HARNESS_GATHERED_TOTAL_RATIO` / `HARNESS_GATHERED_TOTAL_CHARS` | Cap on the memory-write gathered-results block. |

Step budgets are **code constants**, not env: browser intents get `BROWSER_MAX_STEPS=8`, memory delete intents `MEMORY_DELETE_MAX_STEPS=3` (see **1.2**).

### Grounding providers (all SysCtl-overridable, encrypted keys)

| Group | Env prefix(es) | Behavior when enabled |
| --- | --- | --- |
| Serper | `SERPER_API_KEY`, `SERPER_ENABLED`, per-endpoint `SERPER_{WEB,IMAGES,NEWS,PLACES,SHOPPING,REVIEWS,VIDEOS}_{ENABLED,RESULTS}`, `SERPER_SCRAPE_ENABLED` | Adds the eight Serper tools to the classifier vocabulary; per-endpoint knobs set result counts. |
| Bright Data | `BRIGHT_DATA_API_KEY`, `BRIGHT_DATA_SERP_ZONE`, `BRIGHT_DATA_UNLOCKER_ZONE`, `BRIGHT_DATA_ENABLED`, per-endpoint … | Alternative SERP + Web Unlocker provider (no reviews endpoint — broken upstream). |
| YouTube | `YOUTUBE_API_KEY`, `YOUTUBE_ENABLED`, `YOUTUBE_VIDEOS_*` | `youtubeVideoSearch` (Data API v3). |
| EODHD | `EODHD_API_KEY`, `EODHD_ENABLED`, per-endpoint … | Stock-market tools + the stock-data backfill provider; per-endpoint result caps (incl. `EODHD_NEWS_SNIPPET_CHARS`). |
| Sources policy | `SOURCES_PREFERRED`, `SOURCES_BLOCKED`, `SOURCES_IMAGE_TASK_REFERENCE_COUNT` | Hostname/glob/regex lists that rank-boost or drop sources before the model ever sees them; image-task candidate pool size. |

A tool only enters the model's vocabulary when its provider is **enabled AND has a key** (env or override) **and the endpoint flag is on** — see `getEnabledToolNames` in **1.2**.

### Playwright MCP sidecar

| Variable(s) | Behavior |
| --- | --- |
| `PLAYWRIGHT_MCP_ENABLED` | Merges the `browser_*` allow-list into the tool vocabulary (default off). |
| `PLAYWRIGHT_MCP_URL` | Sidecar endpoint (`http://playwright-mcp:8931/mcp` in the network). |
| `PLAYWRIGHT_MCP_TOOLS` | Narrows the exposed browser tools further (empty = the full allow-list). |

### Queues, DLQ, storage, preprocessing, secrets

| Variable(s) | Behavior |
| --- | --- |
| `BULLMQ_HOST/PORT/USER/PASS` + `BULLMQ_CONNECT_TIMEOUT`/`COMMAND_TIMEOUT` + `BULLMQ_USE_TLS`/`BULLMQ_TLS_*` | KeyDB connection incl. TLS. |
| `BULLMQ_JOB_ATTEMPTS`, `BULLMQ_BACKOFF_TYPE`, `BULLMQ_BACKOFF_DELAY`, `BULLMQ_JOB_LIFO/PRIORITY/DELAY`, `BULLMQ_JOB_STACK_TRACE_LIMIT`, `BULLMQ_WORKER_CONCURRENCY` | Retry/backoff policy — introspectable at `GET /bullmq/retry-config`. |
| `BULLMQ_LOG_*` | Job-log appearance (the `@triplef/bullmq-logger` formatting). |
| `DLQ_FAILED_RETAIN` / `DLQ_FAILED_AGE_MS`, `DLQ_CLEARED_*`, `DLQ_REMOVED_*` | How many rows per status the lifecycle keeps and how old they may get (see **1.3**). |
| `FAILED_JOB_RETRY_DELAY_MS`, `FAILED_JOB_REINSTATE_BATCH_SIZE` | Pacing of DLQ reinstatement back into the queue. |
| `MINIO_*` (endpoint/port/SSL/keys/bucket) + `MINIO_TTL_DAYS` | Image-payload store (required at boot); TTL of uploaded originals. |
| `PPROC_*` | Image preprocessing defaults (enable, 768-wide resize, variant set, CLAHE/denoise/sharpen parameters) — live-overridable via `/sharp-overrides` (ephemeral, layer 3). |
| `SOCKET_IO_*` | Gateway: transports, CORS, ping/pong, EIO3 compat (see **1.4**). |
| `TRIPLEF_SECRETS_KEY` (+ `TRIPLEF_SECRETS_KEY_PREVIOUS`) | AES-256-GCM master key for SysCtl-persisted provider keys. **Without it, persisted API keys are kept in memory only** — the UI works, but nothing secret survives a restart. Rotation: old key → `..._PREVIOUS`, boot re-encrypts, then remove (see **1.5**). |
| `MEMORY_URL`, `MEMORY_ENABLED` | Server-side memory client: base URL of the memory app, and the feature gate that decides whether the harness reads/writes memory at all (default on, mirrors the memory app's own `MEMORY_ENABLED`). |

## What each knob changes — memory app (`apps/memory/.env`)

Same boot rules (required: `PORT`, `ADDRESS`, `BODY_LIMIT`, `POSTGRES_URL`, `BULLMQ_*` connection, `OLLAMA_HOST`, `QDRANT_*`).

| Group | Variables | Behavior |
| --- | --- | --- |
| Qdrant | `QDRANT_URL`, `QDRANT_API_KEY`, `QDRANT_COLLECTION`, `QDRANT_EMBED_MODEL`, `QDRANT_VECTOR_SIZE`, `QDRANT_SCORE_THRESHOLD`, `QDRANT_EMBED_TIMEOUT_MS` | Vector store connection; the collection name is namespaced per embedding model; vector size probed from the live model (the env is the fallback); score floor for memory hits; embed-call timeout turns a hung Ollama into a retryable failure. `QDRANT_EMBED_MODEL` owns the vector space and is deliberately **not** runtime-overridable. |
| Feature gate | `MEMORY_ENABLED` | Off = the app behaves as a stateless service: no memory tools, no probes, no post-response jobs. |
| Constellation | `MEMORY_CONSTELLATION_NODE_LIMIT`, `MEMORY_LINK_*` (neighbors, score/topical thresholds, backfill/read bounds) | How big the visible constellation gets; when an edge means relatedness (0.7) vs. suggestion (0.6); bounds for recompute/backfill. Raising thresholds → recompute via `POST /qdrant/memory/links/recompute`. |
| Episode probe | `MEMORY_EPISODE_RECENCY_{WEIGHT,SCALE_SECONDS,MIDPOINT}`, `MEMORY_EPISODE_PROBE_LIMIT`, `MEMORY_EPISODE_SCORE_THRESHOLD` | The recency-blended short-term-memory ranking (see **1.6** §4). |
| Cognition | `MEMORY_COGNITION_LIMIT`, `MEMORY_PROFILE_PAYLOAD_*`, `MEMORY_COGNITION_REFLECT_AUTO` | Profile document cap, profile-job payload caps, auto-reflect flag. |
| Vectorize | `MEMORY_VECTORIZE_TEXT_RATIO`, `MEMORY_VECTORIZE_TEXT_CHARS` | Source-text cap for the extract step. |
| Maintenance | `MEMORY_CONSOLIDATE_{THRESHOLD,MODEL}`, `MEMORY_REFLECT_{MODEL,BATCH_LIMIT,MAX_CANDIDATES}`, `MEMORY_PARTITION_REFLECT_AUTO`, `MEMORY_CONVICTION_{MODEL,BATCH_LIMIT,MAX_PER_CLUSTER,AUTO}`, `MEMORY_CLUSTER_{MODEL,MIN_MEMBERS,AUTO}` | The maintenance pipeline (consolidate → relink → reflect → conviction → cluster): thresholds auto-fire sweeps, models pick the reasoning LLM, batch knobs bound each run, `_AUTO` flags chain the stages without a SysCtl click. All runtime-overridable — see **1.6** §9. |
| Encyclopedia | `ENCYCLOPEDIA_COLLECTION`, `ENCYCLOPEDIA_SELECT_ENABLED`, `ENCYCLOPEDIA_BUDGET_CHARS`, `ENCYCLOPEDIA_CHUNK_CHARS`, `ENCYCLOPEDIA_CHUNK_OVERLAP_SENTENCES`, `ENCYCLOPEDIA_SCORE_THRESHOLD`, `ENCYCLOPEDIA_MAX_CHUNKS`, `ENCYCLOPEDIA_PERSIST_ENABLED`, `ENCYCLOPEDIA_PROBE_LIMIT`, `ENCYCLOPEDIA_NEIGHBOR_EXPANSION`, `ENCYCLOPEDIA_MAX_DOCUMENT_CHARS`, `ENCYCLOPEDIA_CONSOLIDATE_THRESHOLD`, `ENCYCLOPEDIA_CLASSIFY_{MODEL,THRESHOLD}`, `MEMORY_ENCYCLOPEDIA_REFLECT_AUTO` | The knowledge base: master select switch, selection budget, chunking shape, cosine floor, persistence toggle (false = read-through only), probe width + neighbor expansion, oversize rejection, and the maintenance thresholds. |

## Feature flags at a glance

| Flag | When ON | When OFF |
| --- | --- | --- |
| `MEMORY_ENABLED` (both apps) | Memory tools, probes, cognition injection, post-response memory jobs | Harness is a stateless chat; memory app idles |
| `SERPER_ENABLED` / `BRIGHT_DATA_ENABLED` / `YOUTUBE_ENABLED` / `EODHD_ENABLED` (+ per-endpoint flags) | Respective tools enter the classifier vocabulary | Tool absent; intents still work, ungrounded |
| `PLAYWRIGHT_MCP_ENABLED` | `browser_*` allow-list joins the tools | No browser automation |
| `PPROC_ENABLED` | Image variants are generated before model consumption | Originals go straight to the model |
| `ENCYCLOPEDIA_SELECT_ENABLED` | Verbatim passage selection for fetched sources | Select endpoint rejects; fetch falls back to raw text |
| `ENCYCLOPEDIA_PERSIST_ENABLED` | Fetched documents are chunk-indexed for later probes | Ephemeral selection; nothing stored |
| `MEMORY_*_AUTO` / `ENCYCLOPEDIA_…REFLECT_AUTO` | Maintenance stages chain automatically | Stages only run from explicit SysCtl/REST calls |
| `ENABLE_SWAGGER`, `PRINT_CONFIG` | Docs mounted / config dumped at boot | Quieter/smaller attack surface |
| `BULLMQ_USE_TLS` | TLS to KeyDB with the cert knobs | Plain connection |
| `OLLAMA_ENABLE_SMOOTH_STREAM` | Word-level smooth streaming | Raw chunk streaming |

## Effect timing — cheatsheet

- **Boot-only (restart required):** every env variable (both apps) — they are Joi-validated at startup and bound into config services.
- **Next request (persisted):** `/provider-overrides`, `/ollama-overrides`, `/memory-overrides` — written by SysCtl, restored on boot, keys encrypted.
- **Next request (ephemeral):** `/sharp-overrides` — SysCtl preprocessing; env wins again after a restart.
- **Per session:** `/configs/:sessionId` (`harness_config`) — dashboard persists it and pushes on boot.
- **Per turn:** the `POST /harness` query (`numCtx`, `think`, `stream`, `graphRag`, `language`, …).
- **On boot, once:** secrets re-encryption when `TRIPLEF_SECRETS_KEY_PREVIOUS` is set; override restoration (with lazy throttled retry if the database was slow); `qdrant` collection/index bootstrap; DLQ reinstatement of interrupted jobs.
